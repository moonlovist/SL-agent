Constants — Error Keyword Groups

_CONNECTION_ERROR_KEYWORDS

_CONNECTION_ERROR_KEYWORDS = ( "connection reset", "connection refused", "remotedisconnected", "clientconnectorerror", "apiconnectionerror", "connect error", "network", "broken pipe", "eof occurred", "ssl" )

Connection-layer error keywords. Matches used by _is_connection_error to detect network-level failures that should trigger connection reset + retry.

_TIMEOUT_KEYWORDS

_TIMEOUT_KEYWORDS = ( "connectionerror", "connecttimeout", "timed out", "timeout", "readtimeout", "read timeout" )

Timeout error keywords. Matches used by _is_timeout_error to detect timeout conditions that should trigger wait + retry.

_RATE_LIMIT_KEYWORDS

_RATE_LIMIT_KEYWORDS = ( "rate limit", "insufficient_quota", "invalid_parameter_error", "function.arguments" )

API rate-limit / quota error keywords. Matches used by _is_retryable_error to detect throttling conditions.

Check if an error message indicates a timeout condition. On timeout the retry loop waits and retries without resetting the connection.

ParameterTypeDefaultDescription

OutputTypeDescription

_is_retryable_error(error_msg: str) -> bool

Check if an error message is retryable — i.e., it is a connection error, a timeout, or a rate-limit/quota error. Used as the single gate in the retry loop in call_llm_with_context.

ParameterTypeDefaultDescription
error_msgstr—Lowercased error message string to inspect
OutputTypeDescription
retryableboolTrue if connection, timeout, or rate-limit keyword matches

call_llm_with_context

call_llm_with_context(self, system_prompt, user_prompt, image_path=None, parse_json=True, description="LLM output")

Core LLM call method. Assembles messages, selects text/VLM model, retries on retryable errors. JSON parsing: strips markdown fences → json.loads → ast.literal_eval fallback → raw string.

ParameterTypeDefaultDescription
system_promptstr—System prompt for the LLM
user_promptstr—User prompt for the LLM
image_pathOptional[str]NonePath to image file; if set, uses VLM instead of LLM
parse_jsonboolTrueWhether to parse the response as JSON
descriptionstr"LLM output"Human-readable label for logging and error messages
OutputTypeDescription
resultdict | list | strParsed JSON (dict/list) or raw string if parse_json=False
Thinking-mode safety: When want_tools=True and thinking is enabled, _apply_thinking forces thinking to 'disabled'. This prevents the reasoning_content passback issue in LangGraph multi-turn tool calls, where the reasoning token block from a previous turn would be misinterpreted as the current turn's response.
