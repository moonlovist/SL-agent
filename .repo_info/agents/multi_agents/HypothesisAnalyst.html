class HypothesisAnalyst

Inherits: BaseAgent

Harness-based parallel redshift hypothesis verification and ranking. Implements two phases: Phase 1 (single-hypothesis search with bounded concurrency) and Phase 2 (LLM-driven cross-comparison synthesis after FeatureAuditor verification).

run

async run(self, state: SpectroState) -> SpectroState

Phase 1 entry point. Collects redshift hypotheses from state['redshift_hypotheses'] via collect_redshift_hypotheses(). Determines analysis mode from config ("redrock" or "nomad") and stashes it in state['_hypothesis_mode']. Runs the first hypothesis serially to warm the LLM KV cache, then fans out the remaining hypotheses with bounded concurrency governed by params.harness_concurrency. Saves per-hypothesis structured reports and line catalog CSVs. Generates diagnostic feature-overlay plots for each candidate via _plot_harness_candidates(). Sets state['hypothesis_results'] and state['harness_dir'].

If no hypotheses are available, writes a fallback 'UNKNOWN' verdict to state['hypothesis_analysis'] and returns early.

ParameterTypeDefaultDescription
stateSpectroState—Pipeline state with redshift_hypotheses dict, spectrum dict, output_dir, and optional peaks/troughs lists.
OutputTypeDescription
stateSpectroStateUpdated state with hypothesis_results (list of harness result dicts), harness_dir (output path), and _hypothesis_mode set. Diagnostic feature plots written to output_dir/single_hypothesis/.

run_hypothesis_synthesis

async run_hypothesis_synthesis(self, state: SpectroState) -> SpectroState

Phase 2 entry point — runs after FeatureAuditor verification. Reads state['hypothesis_results'] and state['_hypothesis_mode'] set by run(). If FeatureAuditor was skipped or failed (state["feature_audit_verdict"]["skipped"] is true), writes a partial output and raises FeatureAuditorFailed. Otherwise delegates to _run_hypothesis_synthesis() for LLM-driven cross-comparison, then persists the final analysis via ResultWriter.write_hypothesis_analysis().

ParameterTypeDefaultDescription
stateSpectroState—Pipeline state with hypothesis_results, _hypothesis_mode, feature_audit_verdict, and output_dir.
OutputTypeDescription

_run_single_hypothesis_batch

async _run_single_hypothesis_batch(self, state: SpectroState, hypotheses: list, *, mode: str = "nomad") -> list

Execute the single-hypothesis harness across all candidate redshifts. Runs the first hypothesis serially to warm the LLM KV cache (skill prompt + tool definitions), then fans out the remaining hypotheses with bounded concurrency governed by params.harness_concurrency (using asyncio.Semaphore). Each hypothesis invokes single_hypothesis_arun with spectrum data, redshift window (z_half = 0.1 for redrock, 0.005 for nomad), and file output paths. Failed hypotheses are caught and returned as error dicts with an "error" field rather than crashing the batch.

ParameterTypeDefaultDescription
stateSpectroState—Pipeline state with spectrum (wavelength, flux, snr, overlap_regions), file_path, spectrum_npz_path, and optional peaks/troughs.
hypotheseslist—List of hypothesis dicts, each with at least "z" (redshift value).
modestr"nomad"Analysis mode — "nomad" or "redrock"; controls the search window half-width around each hypothesis redshift.
OutputTypeDescription
resultslistOrdered list of harness result dicts, one per hypothesis. Each contains hypothesis_idx, redshift, report, structured_output, feature_catalog, and hypothesis_meta. Failed entries include an "error" key.

_plot_harness_candidates

_plot_harness_candidates(self, state: SpectroState, harness_results: list) -> None

Generate diagnostic line-feature plots for each completed harness candidate. Reads the per-hypothesis {idx}_lines.csv catalog written by the single-hypothesis harness and overlays the adopted rest-frame lines (shifted back to observed frame) on the spectrum flux with continuum. Outputs {idx}_features.png images to the single_hypothesis/ subdirectory. Uses utils.plot.plot_harness_candidate for each result; failed plots are logged as warnings and skipped.

ParameterTypeDefaultDescription
stateSpectroState—Pipeline state with spectrum (wavelength, flux) and optional continuum dict.
harness_resultslist—Ordered harness result dicts; each must have hypothesis_idx and redshift keys for file naming and plot annotation.

_run_hypothesis_synthesis

async _run_hypothesis_synthesis(self, state: SpectroState, hypothesis_results: list, *, mode: str = "nomad") -> None

LLM-driven cross-comparison synthesis. Builds a Dn4000-break diagnostic lookup table via build_dn4000_lookup(), extracts structured summaries from each harness result via a_extract_harness_summaries() (LLM middleware that parses free-text reports into structured verdicts), then delegates to harness.hypothesis_synthesis_arun() for the final combined verdict. Stores the analysis result dict in state['hypothesis_analysis'], which includes redshift, classification, confidence, best hypothesis index, primary evidence, excluded hypotheses, and caveats.

ParameterTypeDefaultDescription
stateSpectroState—Pipeline state with spectrum arrays (wavelength, flux, snr), feature_audit_verdict, and output_dir for report/csv paths.
hypothesis_resultslist—Ordered harness results from _run_single_hypothesis_batch (list of result dicts).
modestr"nomad"Analysis mode forwarded to the synthesis harness.

Pipeline Steps

The HypothesisAnalyst operates in two phases orchestrated by the workflow orchestrator: Phase 1 (run()) executes before FeatureAuditor, and Phase 2 (run_hypothesis_synthesis()) executes after FeatureAuditor has verified the line catalogs.

Phase 1 · Step 1 Single-Hypothesis Search

Collects redshift hypotheses from state['redshift_hypotheses'] (produced by VisualInterpreter). Runs the first hypothesis serially to warm the LLM KV cache, then fans out the remaining candidates with bounded concurrency (params.harness_concurrency). Each hypothesis is processed by the single-hypothesis harness which produces a structured report and line catalog CSV. After all runs complete, diagnostic feature-overlay plots are generated per candidate.

↓
FeatureAuditor verifies line catalogs
↓
Phase 2 · Step 2 LLM Synthesis

Runs the LLM-driven cross-comparison synthesis. First builds a Dn4000-break diagnostic lookup, then extracts structured summaries from each harness result (parsing free-text reports into machine-readable verdicts). Finally delegates to the synthesis harness for a combined verdict: best redshift, classification, confidence level, primary evidence, and excluded hypotheses. The result is persisted via ResultWriter.write_hypothesis_analysis(). If FeatureAuditor failed or was skipped, raises FeatureAuditorFailed with partial outputs.
