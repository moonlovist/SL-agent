Hypothesis Collection

collect_redshift_hypotheses

collect_redshift_hypotheses(data: dict) -> list[dict]

Extract hypotheses from redshift_hypotheses output (Redrock or brute-force). Returns a flat list sorted by score descending, with each entry in the format HypothesisAnalyst expects: z, score, n_lines, details, hypothesis, n_em, n_ab, category. Uses z_representative as the redshift to test; falls back to z_center.

ParameterTypeDefaultDescription
datadict—Redshift hypotheses dict with "hypotheses" list
OutputTypeDescription
hypotheseslist[dict]Flat list sorted by score descending; category = 'low' (z<1) or 'high'

Dn4000 Diagnostics

compute_dn4000

compute_dn4000(wl, fl, z) -> tuple | None

Compute the Dn4000 break index (Balogh+ 1999) for a single redshift hypothesis. Dn4000 = ⟨F(4000–4100 Å rest)⟩ / ⟨F(3850–3950 Å rest)⟩. Returns None if either window has fewer than 3 pixels or the blue continuum mean is ≤ 0.

ParameterTypeDefaultDescription
wlndarray—Observed wavelength grid
flndarray—Flux values
zfloat—Redshift hypothesis to evaluate
OutputTypeDescription
resulttuple | None(dn4000, n_blue, n_red, blue_mean, red_mean, blue_lo, blue_hi, red_lo, red_hi, blue_fluxes, red_fluxes)

build_dn4000_lookup

build_dn4000_lookup(wl, fl, harness_results: list) -> dict

Build a lookup dict mapping rounded redshift → Dn4000 + interpretation for all unique redshifts in harness results. Interpretation: >1.6 = strong, 1.3–1.6 = moderate, <1.3 = weak or absent.

ParameterTypeDefaultDescription
wlndarray—Observed wavelength grid
flndarray—Flux values
harness_resultslist[dict]—Per-hypothesis harness results (z key or redshift)
OutputTypeDescription
lookupdict[float, dict]{z: {"dn4000": float|None, "interpretation": str}}

Harness Report Middleware

_read_csv_lines

_read_csv_lines(csv_path: str) -> list[dict]

Read per-line fitting results from a harness CSV file. Returns a list of dicts with keys: name, rest_wavelength, fitted_center, snr, status, fwhm_km_s, delta_chi2_per_n. Returns empty list if file does not exist.

ParameterTypeDefaultDescription
csv_pathstr—Path to {idx}_lines.csv file
OutputTypeDescription
rowslist[dict]Parsed CSV rows; [] if file missing

_build_line_table

_build_line_table(csv_rows: list[dict]) -> tuple[list[dict], list[str], list[str], float | None]

Build structured line data from raw CSV rows. Normalises line names via normalize_line_name, computes λ_obs and z_implied for each line, sorts by status (LIKELY→MARGINAL→ESTIMATED→NOT_FOUND→SPURIOUS), and computes z_scatter from LIKELY lines (std of z_implied).

ParameterTypeDefaultDescription
csv_rowslist[dict]—Raw CSV rows from _read_csv_lines
OutputTypeDescription
(table_rows, nf, sp, scatter)tupleDetected line rows, NOT_FOUND names, SPURIOUS names, z_scatter

Summary Formatting

format_structured_summary

format_structured_summary(*, hypothesis_idx, z_tested, text_fields, table_rows, not_found_names, spurious_names, z_scatter, dn4000_lookup=None) -> str

Format CSV-derived line data and LLM-extracted text fields into a standardised Markdown block. Structure: header (verdict/classification/Dn4000) → systemic z + σ_z → line table (λ_obs, z_implied, S/N) → NOT_FOUND/SPURIOUS counts → key caveat. Keyword-only arguments.

ParameterTypeDefaultDescription
hypothesis_idxint—Hypothesis index for the header label
z_testedfloat—Redshift value under evaluation
text_fieldsdict—LLM-extracted fields: verdict, classification, systemic_redshift, systemic_source, key_caveat
table_rowslist[dict]—Detected lines from _build_line_table
not_found_nameslist[str]—NOT_FOUND line names
spurious_nameslist[str]—SPURIOUS line names
z_scatterfloat | None—Std dev of z_implied for LIKELY lines
dn4000_lookupdict | NoneNoneDn4000 lookup dict for annotation
OutputTypeDescription
markdownstrStandardised Markdown block for prompt consumption

async a_extract_harness_summaries(harness_results, dn4000_lookup, *, harness_dir=None, model, api_key, base_url, temperature=0.0, concurrency=5) -> list[str]

Async batch extraction for all harness results. Line data comes from per-hypothesis CSV files (deterministic). The LLM only extracts a few natural-language fields (verdict, classification, systemic redshift, caveats) from each report, respecting a Semaphore concurrency limit.
