# LensAgent 当前版本说明

> 当前版本：`0.10.0`
>
> Observation schema（观察文档格式）：`1.8`
>
> 本次主题：把 SEP 与几何 model 串成一条可追溯的候选发现链

## 最直白的变化

旧版把“SEP 已找到的结构”和“沿圆/椭圆路线新找到的结构”分别写入 Observation，容易造成重复计数，也容易让后端把 SEP 误检当成正式证据。

现在改成一条链：

```text
SEP 在全图提出原始线索
→ 原始像素完整留痕，但不直接送去评分
→ 根据中心、SEP 线索和中心后备方案提出圆/椭圆搜索路线
→ 把路线外区域遮住，只在路线内再次运行 SEP
→ 统一生成 C1/C2/... 待审计候选
→ 标定审计完成前，不晋级为后端评分使用的正式结构
```

这里的 model 不是接入了一个新的 AI 模型，而是我们根据强透镜候选的中心几何关系写出的圆/椭圆搜索模型。它只告诉 SEP “再去哪里找”，不证明圆或椭圆上一定有光，更不证明对象一定是强透镜。

## 为什么这样改

1. SEP 是通用源提取软件，只按图像和参数检测连通亮区，不理解“弧、环或多重像”；
2. 单独依赖 SEP 容易把前景星系残差或其他亮块当作候选，也可能漏掉低面亮度环；
3. 单独依赖椭圆又会产生“先画椭圆，再用同一弧证明椭圆正确”的自我证明；
4. 因此 SEP 只负责提出线索，几何模型限制第二次搜索区域，真正的像素仍由 SEP 在原始残差与 RMS 上检测；
5. 原始 SEP、路线和链式候选分层保存，既不丢过程，也不把中间量当结论。

## 本版新增的防误检约束

- `vision_sep_consensus.png`现在画 SEP 分割图中的真实像素并集，不再画固定大小的示意椭圆；
- 即使 SEP 先找到一个无关亮块，程序仍保留中心后备路线，避免错误种子阻断弱环搜索；
- 路径内第二次 SEP 必须继续遵守配置中的搜索内外边界，不能把中心减除残差捞回来；
- 由某个 SEP 块拟合出的路线不能反过来自动证明这个块正确；只有路线相对邻近背景更亮，并且发现独立新像素时，种子才记为“得到几何支持”；
- 未得到支持的 SEP 块仍保存在审计记录中，但不进入紫色模型链候选掩膜，更不参加当前评分。

## 输出怎样理解

- 橙色像素：SEP 原始检测痕迹，保留用于追溯，不代表程序采纳；
- 蓝色圆/椭圆：允许第二次 SEP 搜索的路线，不代表完整环；
- 紫色像素：路线内第二次 SEP 找到的待审计候选，不代表弧、环、多重像或透镜；
- `C1/C2/...`：统一候选编号；每个候选记录来源、状态、位置、S/N、关联路线和前景模型敏感性；
- `structures`：后端评分使用的正式结构。本版在缺少标定晋级规则时保持为空，避免视觉改造未经验证就改变 A/B/C。

## 新增或变化的文件

- `vision_model_chain.png`：四步对照“残差 → 原始 SEP → 模型链候选 → 叠加比较”；
- `vision_sep_consensus.png`：显示真实 SEP 像素，而非示意圈；
- `vision_geometric_path_search.png`：蓝色搜索路线与紫色路径内 SEP 候选；
- `vision_field_context.png`与`vision_rgb_context.png`：把得到几何支持的候选编号映射回完整VIS视场和彩色预览，未解释的原始SEP块不冒充正式定位标记；
- `observation.json.model_candidates`：统一待审计候选；
- `observation.json.geometric_paths`：候选之间的种子、关联与恢复关系；
- `vision_artifacts.npz`：保存原始 SEP 分割、几何种子掩膜、每条路线、每个候选和统一候选掩膜。

## 已完成验证

- 自动化测试：21项全部通过；
- 合成测试覆盖真实 SEP 像素留痕、无种子弱环恢复、错误种子下仍保留中心后备路线、路径搜索不越过中心内边界；
- 真实样本`102019123_NEG567245233502945885`完整运行成功：原先错误的大块被保留为未解释的橙色审计痕迹，中心内边界以内伪残差被排除，环附近留下一个路径内候选；
- 本结果证明链路行为符合设计，不证明完整环已经恢复，也不证明 A/B/C 准确率提高。

## 下一步

1. 用专家圈出的真实弧、环和非目标结构建立像素级标注；
2. 标定候选的合并、拒绝和晋级规则；
3. 增加环段组合与多重像组合测量；
4. 在独立验证集上确定参数和 A/B/C 等级映射；
5. 只有完成上述验证后，才让模型链候选进入后端证据评分。
