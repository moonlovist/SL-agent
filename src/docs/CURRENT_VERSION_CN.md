# LensAgent 当前版本说明

> 当前版本：`0.12.0`
>
> Observation schema（观察文档格式）：`1.11`
>
> 本次主题：候选结构审计与后端交付

## 本次解决了什么

上一版已经能把视觉检测结果拆成三类候选：路线内原SEP结构、路线内补充恢复结构、路线外降级留痕结构。但它们全部停在`model_candidates`，后端规则层仍收不到任何`structures`，所以视觉链和专家推理链实际上没有接通。

本版本在两者之间增加`CandidateStructureAudit`（候选结构审计）：

```text
视觉层提出 model_candidates
↓
候选结构审计
├─ promoted：生成可测量 structure，交给后端比较解释
├─ hold_for_review：风险过高，暂缓并交人工复核
└─ trace_only：保留全过程，但不进入后端证据比较
↓
多假设证据比较、反证、决策审计与报告
```

它只判断“该候选是否足以作为一个可测量残差结构交给后端”，不判断“它是不是透镜”。弧、环、多重像、前景星系自身结构和减除伪影仍由后续多假设推理比较。

## 审计检查什么

审计使用视觉链已经产生的事实，不再新增一套透镜分数：

- 输入数据是否可用于测量；
- 候选是否只有一次SEP检测，还是同时具有几何路线或路线恢复支持；
- 换用审计用PSF-MGE前景模型后，候选是否被完全抹掉；
- 是否使用了备用前景模型、是否近中心、比较模型是否不可用等风险。

只有数据本身不可用才直接暂缓。精细前景拟合失败但备用模型可用时，不会把所有候选一票否决，而是保留`primary_foreground_fit_used_fallback`风险标记交给后续审计和报告。

## 三种结果怎样理解

| 结果 | 中文含义 | 是否进入`structures` | 是否等于强透镜证据 |
|---|---|---:|---:|
| `promoted` | 具备可测量结构所需的处理支持 | 是 | 否 |
| `hold_for_review` | 存在关键处理风险，暂缓 | 否 | 否 |
| `trace_only` | 是真实的检测留痕，但缺少第二种结构支持 | 否 | 否 |

`promoted`不是“高置信度透镜”，只是“可以交给后端解释的结构”。后端仍必须比较强透镜、星系自身形态、并合和伪影等竞争解释。

## 新增可追溯内容

`observation.json`新增`candidate_structure_audits`，每项记录：

- 候选编号与审计编号；
- 三态审计结果；
- 每项检查是否通过、失败或无法检查；
- 支持事实、风险标记和文字理由；
- 若晋级，明确对应哪个`structure`。

每个正式`structure`反向保存`source_candidate_ids`和`candidate_audit_ids`。因此可以从后端证据一路追溯到候选、SEP像素和处理图。

## 当前边界

- 视觉检测方法和已有参数没有在本次继续加严；
- 审计没有把候选分类成弧、环或多重像；
- 没有新增一个未经标定的总分或概率；
- 视觉候选并未被删除，暂缓和追溯项仍保存在JSON、NPZ和中文摘要中；
- 当前晋级逻辑是透明的工程基线，仍需用专家标注的正例、困难正例和污染样本标定其召回率与误晋级率。

## 本次验证

- 30项自动化测试全部通过；
- 困难样本`102019123_NEG567245233502945885`完整运行成功；

这次单样本验证只证明软件流程和证据边界符合设计，不代表审计阈值已经达到统计意义上的高准确率。
