# LensAgent 现阶段修改、审计规则与完整流程（初中生版）

> 历史说明：本文主体记录 v0.18.0。当前 v0.19.0 已改变前景中心选择、弯曲结构测量和独立模型比较的使用方式，
> 请先读 [v0.19.0 修改说明](V0190_CENTER_STRUCTURE_CHANGE_CN.md)，不要把本文旧阈值解释直接视作最新版规则。

> 适用版本：LensAgent `0.18.0`，Observation（观察记录）格式 `1.14`
>
> 这份说明按当前实际代码编写。为了容易理解，先讲直觉，再讲真实规则和数值。

## 一、先用一句话说清整个系统

LensAgent 做的事情不是“看一眼图片，算一个总分”。它更像一支分工明确的调查队：

1. **视觉测量层**先把中心亮星系尽量减掉，寻找剩下的亮结构；
2. **候选结构审计层**逐个判断这些亮结构值不值得交给后面，但这一步不判断是不是透镜；
3. **专家评级层**把通过审计的结构放回整张图的空间关系中，比较“强引力透镜”和其他解释，然后只选一个 `A/B/C/X` 类别；
4. **判决审计层**检查专家有没有引用不存在的数据、重复计算同一证据、把缺失信息当反证等错误。

如果只数名称中带“审计”的层，是两层：候选结构审计和判决审计。

如果按一个目标真正经历的科学关卡来数，是三道审核：

1. 信号真实吗？
2. 它们组成了像透镜的构型吗？
3. 刚才的判决过程合规吗？

在这三道审核之前，还有一整套视觉测量。因此最容易理解的说法是：**一套测量，加三道审核，最后写报告。**

## 二、什么是强引力透镜

可以把前景星系想成一块放在宇宙中的放大镜。更远处天体发出的光经过它附近时会被弯曲，于是我们可能看到：

- 一段弯弧；
- 半个圆环或接近完整的圆环；
- 同一个背景天体的两个、三个或四个像；
- 靠得很近、像要合并的两段弧；
- 一条沿圆周方向伸展的弧和一条指向中心的弧。

困难在于，前景星系自己的旋臂、星系碰撞、减除失败、仪器点扩散、噪声和坏像素，也可能留下类似亮斑。所以“检测到亮东西”和“证明是透镜”是两件不同的事。

## 三、几个必须先分清的名词

### 1. 候选信号

程序在残差图中检测到的一小片连通亮像素。它可能是真实天体，也可能是噪声或减除残留。

### 2. 正式结构

候选信号通过候选结构审计后，获得完整的形状、位置和稳定性测量，才成为后端能正式使用的结构，编号通常是 `S1`、`S2` 等。

### 3. 几何路线

程序根据中心和已发现结构画出的圆形或椭圆形“搜索走廊”。它只是告诉程序可以去哪里继续找弱信号，不代表走廊本身真的发光，也不代表它就是爱因斯坦环。

### 4. 恢复候选

“恢复”表示这个信号不是沿主要路线交接，或者是通过路线内补找得到的。它是**来源说明**，不是“低质量”或“低一级”。

### 5. 构型

构型就是多个亮结构相对于中心怎样排列，或者单个结构具有什么足够特别的形状。例如切向弧、折叠弧、尖点弧和四重像都是不同构型。

## 四、从原始图像到候选池

### 第 0 步：读取图像

科学运行优先读取 FITS 文件。FITS 不只是普通图片，它还可能包含亮度、噪声、望远镜点扩散函数和天空坐标。PNG 可以运行，但缺少很多科学信息，因此证据等级不完全相同。

### 第 1 步：寻找中心前景星系

透镜候选图中央通常有一个很亮的前景星系。程序先估计它的中心、大小和光分布。

### 第 2 步：减去前景星系

程序建立前景星系光模型，再用原图减去模型：

```text
原图 - 中央前景星系模型 = 残差图
```

残差图里希望留下被弯曲的背景源，但也可能留下模型减得不准的部分。

当前还有一个独立的、考虑点扩散函数的比较模型。它的任务是检查某个结构是否只在一种减除办法下出现。这个比较模型不参与第一次检测，避免程序一边找答案一边改变答案。

### 第 3 步：制作信噪比图

信噪比可以粗略理解为“亮结构比背景起伏明显多少”。程序使用：

```text
残差 ÷ 噪声 = 残差信噪比图
```

信噪比高说明“检测得到”，但不等于“这是透镜”。一个减除伪影也可能很亮。

### 第 4 步：在多个亮度门槛下重复观察

程序使用八个信噪比门槛：

```text
2.00、2.58、3.34、4.31、5.57、7.19、9.29、12.00
```

如果同一片连通信号能在多个门槛下保留下来，它比只在一个很低门槛下闪现的信号更稳定。当前候选交接要求至少在 8 层中的 3 层存活，才叫“多门槛稳定”。

这只是稳定性测试，不是 A 级门槛。

### 第 5 步：SEP 多参数检测

SEP 是一个寻找天文图像中连通亮区的工具。程序用多组“怎样拆开粘在一起的亮区”的参数运行 SEP，再保存共同或可追溯的像素。

一大块粘连区域会尽量被拆成局部部分，避免真实弧、中心残差和路线外污染被当成同一个整体。

### 第 6 步：几何路线搜索与弱结构恢复

程序用已检测结构和中心生成圆形、椭圆形搜索路线，并在路线带内再次调用 SEP 寻找遗漏片段。这里有三条防止“自己证明自己”的规则：

1. 路线中的空白不能被填成虚构信号；
2. 生成路线的种子不能仅凭自己生成的路线证明自己；
3. 路线、原始 SEP 和恢复结果共享同一张残差图，因此不能当成三票独立证据。

完成后得到“模型候选池”。池中每个候选都保留精确像素、发现来源、信噪比稳定性、路线关系和前景模型敏感性。

## 五、第一道审核：候选结构审计

这一层只问：**这片亮结构是否是真实、可测、值得交给专家层的信号？**

它绝不回答“是不是透镜”。

### 1. 每个候选先检查的基本事实

- 整张图是否可用；
- 候选是否有检测器支持；
- 是否真的包含连通像素；
- 总信号是否为正；
- 是否在至少 3 个信噪比门槛下存活；
- 是否和几何路线有关；
- 独立前景比较模型有没有把它完全擦掉；
- 是否靠近最容易减除出错的中心。

检测器支持可以来自全图 SEP，也可以来自路线内再次 SEP 搜索。几何关系不用于证明信号真实。

### 2. 四条交接通道

#### 绿色：主要候选 `primary_candidate`

需要满足：

- 图像可用；
- 有检测器支持、连通像素和正信号；
- 至少在 3 个门槛下存活；
- 有几何路线关系；
- 没有被独立比较模型完全擦除。

结果是 `promoted`（晋级），生成正式结构并进入评级层。

#### 青色：恢复候选 `recovery_candidate`

有两种情况：

1. **稳定但没有路线支持**：现在会晋级，生成正式结构，带着“恢复来源”进入评级层；
2. **有路线支持但多门槛稳定性较弱或缺失**：不会删除，而是 `hold_for_review`（留待复核），不生成等权正式结构。

v0.18.0 最关键的修改之一，就是第一种青色候选不再被挡在评级层外。真正稳定的长弧即使没有命中原先的椭圆路线，也必须让专家看到。

#### 红色：前景污染候选 `foreground_contaminated`

当前只有在独立比较前景模型把候选**完全擦除**时，才隔离为红色。

靠近中心、主前景模型拟合失败或没有路线支持，都只能算风险提示，不能单独把真实结构标红。这修复了早期版本把真实中心附近结构一起清理掉的问题。

#### 橙色：追溯候选 `trace_candidate`

图像不可用，或者候选缺少基本检测事实，或者既不稳定又没有几何支持时，只保留追溯记录。它不会成为当前评级的正式正向结构，但像素和原因不会被删除。

### 3. 候选审计不是一条直线式淘汰赛

它更像分流站：

```text
所有视觉候选
├─ 稳定 + 有路线 ─────────→ 主要候选 → 正式结构
├─ 稳定 + 无路线 ─────────→ 恢复候选 → 正式结构
├─ 有路线但稳定性不足 ────→ 恢复候选 → 留待复核
├─ 独立模型完全擦除 ──────→ 前景污染 → 隔离、保留记录
└─ 基本信号不足 ──────────→ 追溯候选 → 只留记录
```

“恢复”和“留待复核”都不是把结果送回视觉层重新调参。当前一次完整运行中没有自动回环。

## 六、Observation：视觉层和专家层之间的防火墙

第一道审核结束后，程序写出 `observation.json`。它只记录“机器看到了什么”，例如：

- 每个正式结构的位置、半径和方位；
- 它有多长、多细；
- 它相对中心是沿圆周方向还是指向中心；
- 它在多个门槛和不同前景模型下是否保留；
- 它来自主要通道还是恢复通道；
- 哪些候选只留待复核或追溯。

视觉层禁止在这里写“透镜”“非透镜”或透镜概率。

专家评级层只读取这份 Observation，不重新打开像素图。这让我们可以检查：如果评级错了，究竟是视觉层漏交结构，还是专家规则解释错了。

## 七、第二道审核：专家评级层

活动流程中只有一个主要专家：`ExpertAssessmentAgent`。它进行一次整体判断，不是许多小 Agent 轮流投票。

### 第 1 问：数据够不够用

主要条件是：

- 有效像素比例至少约 99%；
- 背景噪声大于 0；
- 残差噪声大于 0；
- Observation 标记图像可用。

如果数据不够，输出 `insufficient_for_grading`，中文是“数据不足，无法评级”。它不是 X，因为“看不清”不等于“不是透镜”。

### 第 2 问：交来的信号真实吗

必须有正式结构，并且满足下面至少一种情况：

- 独立前景比较模型仍保留至少 50% 的正式结构像素；
- 大约至少一半正式结构在多门槛或 SEP 检测中有持续性。

满足时叫“信号可信”。仍然只说明亮结构可信，不说明它一定是透镜。

### 第 3 问：这些结构形成了哪一种透镜构型

当前会检查八种构型。

#### 1. 环或部分环

结构围绕同一中心形成环状或较完整的部分环。环带跨度只是描述量，不单独决定等级。

#### 2. 切向弧

“切向”可以想象成：在圆周某一点画一条沿圆边前进的线。透镜弧常沿着以中心星系为圆心的圆周方向伸展。

当前用来识别切向结构的辅助范围包括：

- 长轴与理想切向方向的偏离不超过 35°；
- 形状轴比至少 1.5，也就是明显拉长；
- 环向跨度至少 20°。

更稳健的单弧通常还要求：

- 不在敏感中心内；
- 环向跨度至少 30°；
- 在信噪比门槛中有存活；
- 独立前景模型总体保留至少 75% 的正式结构像素。

这样的单条或部分长弧可以直接形成“清晰构型”，不再强迫它必须有第二条同样亮的反像。

#### 3. 折叠弧

两条靠近、半径相容的切向结构，可能其实是一对正在合并的透镜像。辅助条件包括两段之间沿圆周相隔不超过 60°。

#### 4. 尖点弧

三条在同一侧聚集、半径相容的切向结构。三条所占圆周范围不超过约 100°时，会被当作尖点构型检查。

#### 5. 径向弧

长方向更接近“指向中心”的结构。当前用切向偏离至少 65°并且轴比至少 1.5来寻找。径向弧需要和可信切向结构共同出现，才能成为高可信构型。

#### 6. 紧致多像

多个短小图像围绕中心分布，例如双像、四像或爱因斯坦十字。当前高可信紧致多像辅助条件包括至少四个短结构、半径相容并围绕至少半圈。它不要求出现长弧。

#### 7. 非对称多像

一条很强的弧加上更弱、被遮挡或还处于留待复核状态的对应像。它用于防止程序错误要求每一幅像必须一样亮、一样长、一样对称。

#### 8. 单像

孤立且没有明显透镜方向关系的单个结构。普通单像不能只靠“它很亮”升为 A。

这些角度和长度是**识别不同构型的辅助范围**，不是“超过某个数自动加分”的总分表。最终 A 仍然要求完整条件同时成立。

### 第 4 问：是否形成“清晰构型”

当前代码把以下任一路径视为可能形成清晰构型：

1. 传统统一系统：多个结构半径较一致、总体切向关系合理、覆盖范围足够，而且至少一半结构不在中心敏感区；
2. 稳健的单条或部分切向弧；
3. 符合条件的折叠弧；
4. 符合条件的尖点弧；
5. 切向弧加径向弧；
6. 符合条件的紧致多像。

传统统一系统使用的辅助量包括：

- 共同半径离散程度不大于 0.30；
- 平均切向偏离不大于 25°，或者至少 67% 的结构切向对齐；
- 最低总体覆盖约 60°，清晰传统系统通常要求 90°；
- 至少一半正式结构不在中心敏感区。

这里的“或者”很重要：A 级不再只有“多段弧 + 同半径 + 长覆盖”一条窄路。

### 第 5 问：有没有同样强的非透镜解释

系统同时比较五种解释：

1. 强引力透镜；
2. 前景星系自己的形态；
3. 星系并合或相互作用；
4. 前景减除或点扩散伪影；
5. 噪声、坏像素或碰巧投影在一起的普通天体。

当前会阻止清晰构型直接升为 A 的“同样强替代解释”主要有：

- 独立比较模型保留的正式结构像素少于 50%，或者超过一半正式结构都挤在敏感中心；
- 主前景模型失败，而且独立模型也不能把结构保留率提高到至少 75%；
- 至少 2 个结构连到内部、潮汐不对称代理至少 0.65，同时中心残差比例至少 0.50；
- 检测到多个亮核心，支持星系并合解释。

单独一个“图像不对称”代理不会压过清晰、跨模型稳定的透镜构型；靠近中心也不会单独把候选删除。

## 八、A、B、C、X 到底怎样产生

当前没有加权总分，也没有 `B-A` 中间等级。一个 Agent 模拟一名专家，只选一次类别。

### A：高可信候选

必须同时满足：

1. 数据可用；
2. 信号可信；
3. 至少一种可以达到高可信的透镜构型足够清晰；
4. 没有由 Observation 实测支持、强度相当的非透镜解释。

可以简写成：

```text
A = 数据够用 + 信号可信 + 清晰透镜构型 + 没有同样强的非透镜解释
```

注意：不是“找到两个结构就是 A”，也不是“弧长超过 30°就是 A”。那些数值只帮助确认某一种构型；信号稳定性、独立模型和替代解释仍要一起通过。

### B：很像透镜，但还需要确认

有两条常见路径：

1. 已有清晰透镜构型，但存在同样强的非透镜解释；
2. 信号可信，也有透镜方向或空间关系，但尚未组成足够清楚的高可信构型。

### C：有类似透镜的特点，但证据不完整

例如：

- 留待复核的可测候选看起来像透镜结构，但提取冲突较大；
- 有拉长或径向结构，却缺少完整系统关系；
- 有可信残差信号，却没有足够透镜特异的排列。

### X：当前可用信息更像非透镜

图像本身可用，但没有可信的透镜特异空间关系，噪声、伪影或普通星系解释更合适。

### 数据不足：不投 X

图像或噪声信息不足时输出 `insufficient_for_grading`，不强行评级。

## 九、第三道审核：DecisionAudit 判决审计

专家选完类别后，`DecisionAudit` 做一次轻量质检。它检查：

1. 报告引用的事实是否真的存在于 Observation；
2. 是否把“没有颜色、没有光谱、没做质量模型”等缺失信息错误写成反证；
3. 是否把来自同一批像素的相关测量重复当成多票；
4. 是否拿高信噪比、路线一致等普通测量直接当作透镜证明；
5. 是否因为候选来自恢复通道就自动扣级；
6. 是否漏掉五种必须比较的解释；
7. 是否偷偷读取正式标签、已知透镜身份或外部答案；
8. 类别、兼容字段和文字理由是否互相冲突；
9. 数据不可用时是否应该弃权。

这一层**不会重新分析八种构型，不会产生第二个等级，也不会把多个结果平均**。如果发现问题，它把 `audit_passed` 设为 `false` 并列出需要修正的项目。报告仍会诚实记录审计未通过，而不是悄悄改成另一个字母。

因此，“DecisionAudit 通过”只表示判决过程在这些规则下自洽、可追溯，不等于这个天体在真实宇宙中一定分对了。

## 十、有没有返回、复用和复杂循环

### 1. 当前完整运行是单向流程，没有自动返回循环

```text
图像 → 一次视觉处理 → 一次候选审计 → 一份 Observation
     → 一次专家综合判断 → 一次判决审计 → 报告
```

不会发生下面这些行为：

- 因为想升 A，就返回视觉层改椭圆；
- 审计失败后自动调低门槛重跑；
- 找到一段弧后不断沿路线迭代扩张；
- 多个旧 Agent 来回投票直到意见一致；
- 根据对象编号或已知 A 标签改答案。

### 2. “恢复候选”不是返回上一步

它只是当前候选审计中的另一条交接通道。稳定的青色恢复候选现在和绿色主要候选一样生成完整正式结构，但保留不同来源标签。

### 3. “留待复核”不是自动排队重跑

它表示保留像素、测量和原因，供报告或以后新的专项工具检查。当前这一次运行不会自动再次晋级它。

### 4. 哪些东西会复用

- 多门槛检测、SEP、几何路线都复用同一份前景减除残差；
- 多项形状和稳定性测量可能来自同一批像素；
- `lens-agent reason` 可以人工选择复用已经冻结的 `observation.json`，只重跑评级层。

这些复用都被记录为相关证据，不能假装成互相独立的多位专家投票。

### 5. 历史 Agent 文件还在，但没有运行

旧的假设 Agent、证据 Agent、反证 Agent、推理审计 Agent 等文件为了 Git 回退和历史追溯仍保留在仓库中，但当前活动流程没有调用它们。现在只有一个主要专家判断和一个轻量判决审计。

## 十一、我们这一阶段究竟改了什么

### v0.12：补上候选到正式结构之间的桥

以前视觉层发现候选后，怎样进入后端不够透明。我们加入逐候选结构审计，以及“晋级、留待复核、只留追溯”三种结果，并让正式结构能反查原候选和像素。

### v0.13：把信号真假和几何路线拆开

以前没有命中路线的结构容易被挡住。我们改成所有候选都接受同样的信号审计，路线只记录发现背景，不再证明信号真假。

### v0.14：加入四路交接

候选被分成主要、恢复、前景污染、追溯四类。这样不必把所有信号等权交给评级，也不必直接删除有争议的结构。

### v0.15：删除没有标定依据的临时总分

旧的加权分、信心分和假设分不是 Q1 论文的正式专家分数，因此退出活动流程。系统明确区分单专家类别和未来多专家聚合分数。

### v0.16：把后端收成一次专家综合判断

旧版许多 Agent 容易造成重复证据和“像多人投票”的错觉。我们改成唯一的专家层一次性建立证据档案、比较解释并选类别；之后的 DecisionAudit 只检查错误。

### v0.17：改成类别优先

Agent 先选 `A/B/C/X`，不再先造一个数字再切等级，也不再输出 `B-A` 这种论文专家没有选择的中间类别。

### v0.18：修复真实结构丢失，并扩展 A 级构型

这是本阶段最重要的升级：

- 稳定的青色路线外候选可以生成正式结构；
- 接近中心和主模型失败只作为风险，只有独立模型完全擦除才标红；
- A 不再强制要求多个结构、固定 60° 长弧或统一切向关系；
- 加入环、切向弧、折叠弧、尖点弧、径向弧、紧致多像、非对称多像和单像八种构型；
- 单条稳健切向弧也可以支持 A；
- 内连、不对称和中心残差只有组成更完整反解释时才能压低清晰透镜构型；
- 数字分数字段保持空值，只输出一个专家类别。

底层 FITS 读取、前景建模、SEP、多信噪比门槛和几何路线算法在 v0.18 没有修改；修改重点是“候选怎样交给后端”和“后端怎样理解多种构型”。

## 十二、例子一：青色恢复结构怎样进入 A 级判断

以 `102019588_NEG579781735502176069` 为例。

### 候选审计

- `C1`：稳定且有路线支持，成为绿色主要候选，晋级为 `S1`；
- `C2`：稳定但走恢复通道，成为青色恢复候选，仍晋级为 `S2`；
- `C3`：有几何关系但稳定性不足，保留为待复核恢复候选，没有生成正式结构。

这说明青色不是被扔掉，也不是自动降级。可信的青色 `C2` 拿到了和绿色候选一样完整的结构测量，只额外保留“从哪里来”的标签。

### 专家判断

主要结构 `S1` 的实际测量大致是：

- 环向跨度约 175.7°；
- 轴比约 2.29，明显拉长；
- 切向偏离约 14.1°；
- 在 8 个门槛中约 87.5% 的层级仍能看到；
- 不在敏感中心。

因此切向弧构型得到支持。信号可信，透镜构型清晰，未出现强度相当的非透镜解释，最后选择 A。这里不是因为“175.7°对应多少分”，而是它帮助确认了一个稳定、拉长、方向合理的切向弧构型。

## 十三、例子二：结构很多、构型也像透镜，为什么仍可能是 B

以 `102018668_NEG595646727509469177` 为例。

### 候选审计

视觉层共有 10 个候选：

- 3 个主要候选晋级；
- 5 个稳定的恢复候选晋级；
- 2 个较弱恢复候选留待复核。

最终有 8 个正式结构进入专家层。旧逻辑可能把 5 个青色恢复结构挡住；v0.18 已经把它们交全，所以这次 B 不能简单归因于“青色没进去”。

### 专家判断

它支持多条切向弧，也支持切向加径向结构，说明透镜解释确实很强。但 Observation 同时测到：

- 1 个额外亮核心；
- 较高的残差不对称代理；
- 若干和内部相连的结构。

其中“多个亮核心”让星系并合解释进入“仍然有竞争力”的状态。当前 A 规则要求没有同样强的实测非透镜解释，所以它被投为 B：很可能是透镜，但还需要更多数据确认。

我们知道它属于提供的 A 样本，因此这是当前系统的一次假阴性，而不是应该掩盖的成功。它说明替代解释的规则仍需用更多正例、困难负例和独立盲测集校准。

## 十四、例子三：为什么 DecisionAudit 通过仍可能与已知标签不同

上面这张图的 DecisionAudit 通过了，因为：

- 每个结论都有 Observation 引用；
- 没有把缺失颜色或光谱当反证；
- 没有把恢复来源自动扣级；
- 五种替代解释都比较了；
- 类别 B 与文字理由一致；
- 没有读取已知 A 标签。

但是“逻辑过程合规”不等于“科学阈值已经校准正确”。所以它可以审计通过，同时仍与人类已知 A 标签不同。这正是为什么还需要更大的标注集和盲测。

## 十五、当前八张 A 样本告诉了我们什么

使用 v0.18.0 完整重跑目前八张已知 A 样本后：

- 6 张被评为 A；
- 2 张被评为 B；
- 0 张被评为 C 或 X；
- 8 张判决审计全部通过；
- A 级召回率为 75%。

这说明候选交接问题明显改善，尤其是青色恢复结构和被误标红结构能够进入判断；但两张 B 表明评级层对某些并合代理或“不够统一”的情况仍偏保守。八张正例也不足以测量误报率，因为还必须加入大量真实非透镜和困难负例。

## 十六、它和 Q1 论文的关系

Q1 论文中，一名专家先选择 `X/C/B/A/A+`。之后把约十位专家的选择编码为 `0/1/2/3`，校正专家偏松或偏严的差异，再聚合成连续 `expert_score`，最后按分数分箱。

当前 LensAgent 只模拟其中“一名专家选择类别”的步骤：

```text
当前：一套机器观察 → 一个 Agent 专家 → 选择 A/B/C/X
论文：约十名人类专家 → 各自选择类别 → 编码 → 偏差校正 → 聚合分数 → 目录分箱
```

因此当前这些字段保持空值：

- `vote_code`；
- `expert_vote_anchor`；
- `provisional_expert_score`；
- `provisional_score_range`；
- `official_expert_score`。

Q1 论文目录的 A/B 分界仍可作为未来聚合分数的正式映射：A 为分数大于 2.0，B 为大于 1.5 且不超过 2.0。但不能把当前单 Agent 的一次类别选择假装成十名专家聚合出的连续分数。

建议按下面顺序看：

1. `vision_diagnostic.png`：原图、前景模型、残差和总体候选；
2. `vision_snr_threshold_process.png`：信号在不同门槛下怎样存活；
3. `vision_sep_consensus.png`：SEP 找到了哪些连通像素；
4. `vision_geometric_path_search.png`：搜索路线在哪里，实际又找回了什么；
5. `vision_model_chain.png`：原始 SEP、路线支持和路线恢复之间的关系；
6. `vision_foreground_model_comparison.png`：换一个前景模型后结构是否还在；
7. `vision_signal_audit.png`：绿色、青色、红色和追溯候选怎样交接；
8. `observation_summary_cn.md`：视觉事实的中文摘要；
9. `reasoning.json` 或 `summary.json`：八种构型、五种解释、类别和审计结果；
10. `report.md`：最终人工可读报告。

## 十八、最后用最短的话复述

一个目标要成为 A，不是靠一个大数字，也不是只靠一条硬门槛。它必须经历：

```text
发现亮结构
→ 确认结构可测且稳定
→ 把主要和可信恢复结构完整交给专家
→ 确认至少一种清晰透镜构型
→ 确认没有同样强的非透镜解释
→ 专家选择 A
→ DecisionAudit 检查整个说法是否自洽可追溯
```

当前没有自动返回调参循环；“恢复”只是保留真实结构的交接通道；“复用”会被标成相关证据，不能重复算票；最终只有一次单专家类别投票，数字专家分数为空。
