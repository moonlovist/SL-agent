## 1. 它是一套什么样的软件

可以把它理解为一个分工明确的“图像检验工作台”：前半段用尺子和计算器测图，后半段依照公开的判断表解释测量，最后检查记录是否一致。

这里的 agent 是承担任务的程序模块，不自动等于 ChatGPT 这样的聊天模型。

当前实际情况：

- 用 Python 编写。Python 是让计算机执行一串明确指令的编程语言。
- 主要使用传统图像处理、数值计算和固定规则。
- 不调用大语言模型或多模态模型 API，不需要模型服务密钥。
- 不用神经网络“看完图直接猜等级”，也不会在运行一个目标后自动学习、修改规则。
- 参数拟合不等于 AI 训练：本项目拟合的是这一张图的前景亮度，而不是训练一个识别所有星系的模型。
- 正常计算由本地计算机完成，当前流程不要求 GPU。安装依赖可能需要网络，评级本身不依赖在线问答。

“专家判断模块”目前仍是专家经验的规则化近似，不能因为名字带 Expert 就理解为具有完整的人类天文判断能力。

### 几种容易混淆的“模型”

| 名称 | 在本项目里是什么意思 | 本版是否实际使用 |
|---|---|---|
| 前景光模型 | 用数学形状估计近处星系自身的亮度分布 | 使用 |
| 几何路线模型 | 画出一条可能沿着弧走的搜索带 | 使用 |
| 大语言/多模态模型 | 从训练中学会理解文字、图像的 AI | 未接入 |
| 引力透镜质量模型 | 用引力方程解释质量如何把背景源变成多个像 | 不属于当前评级主流程 |

所以 model chain 主要指图像处理和几何搜索的连续步骤，不是几个聊天 AI 接力，也不是已经完成质量建模。

## 2. 先认识最常见的天文与图像词语

### 2.1 图像中的天体和形状

- 星系：大量恒星、气体等组成的系统。在这类小图里，常表现为亮斑或椭圆亮团。
- 前景：在我们的视线方向上相对较近的天体。它的亮光可能遮盖后方目标的细节。
- 背景源：更远处发光的天体。此处“背景源”不同于下面说的“天空背景噪声”。
- 弧，arc：弯曲的发光结构。
- 多像：同一个背景源形成不止一个像；不是“图中只要有几个亮块就算多像”。
- 环/局部环：绕中心延伸的结构，可能完整，也可能只有一段。仅凭像环还不能断言它一定由透镜产生。
- 核区：前景星系中心附近的亮区。前景减除在这里通常更敏感。

这些是描述和假设。软件发现“弧状像素”，不等于已经知道它是哪一种物理结构。

### 2.2 图像就是一张数字表

- 像素：数字图像里的小格子。
- 坐标：格子的横向位置 x 和纵向位置 y。数组在代码里常按 y、x 存放，所以会同时看到 xy 和 yx；顺序不能弄反。
- 通量：记录的光信号量。可以先理解为可相加的亮度数值，不要直接当作人眼看见的屏幕亮度。
- 噪声：测量中的随机起伏。看起来略亮的小点，可能只是噪声波动。
- 波段：观察哪一段波长范围的光。默认 VIS 是可见光波段。
- 角秒：描述天空上两个方向相隔多远的角度单位；1 度等于 3600 角秒。像素距离要通过图像尺度才能换成角秒。

### 2.3 处理过程中的词语

| 词语 | 零基础解释 | 不应误解成 |
|---|---|---|
| 掩膜 mask | 给每个像素打“选中/没选中”的标签 | 涂掉或改写原始照片 |
| 分割 segmentation | 给不同亮块贴不同编号 | 已识别出每块的真实天体身份 |
| 连通块 | 按规定邻接方式连起来的一组像素 | 一定是一个独立天体或一个透镜像 |
| 拟合 fit | 调整数学形状的参数，使它尽量贴近数据 | 拟合成功就证明物理解释正确 |
| 残差 residual | 数据减去模型后剩下的差值 | 剩下的必定全是背景透镜光 |
| 阈值 threshold | 超过或低于某个值时走不同分支 | 宇宙中不可违背的规律 |
| 规则/启发式 | 人写的、便于计算的经验判断办法 | 已用大样本证明正确的标准 |
| 来源 provenance | 这个像素或数值是从哪里、怎样得到的 | 独立支持它为真的新证据 |
| 审计 audit | 检查输入、引用、推导和输出是否对得上 | 第二位独立天文学家确认了结果 |

## 3. 输入文件里究竟有什么

### 3.1 FITS 不是普通截图

FITS 是天文常用的数据容器。可想成一本带有多页数字表和说明页的工作簿：既能放图像像素，也能放误差信息和坐标说明。程序用 Astropy 读取它。[Astropy FITS 文档](https://docs.astropy.org/en/stable/io/fits/)

默认波段下，程序优先寻找：

| 数据 | 文件中常见名字 | 作用 |
|---|---|---|
| 光信号图 | VIS_FLUX | 每个位置记录了多少光 |
| 噪声图 | VIS_RMS | 每个位置大致有多大测量波动 |
| 点源模糊模板 | VIS_PSF | 一个非常小的光点经过仪器后会被拍成多大的模糊斑 |
| 天空坐标说明 | 图像头里的 WCS 信息 | 将像素位置换成天空方向 |

RMS 可先理解为噪声大小的估计。PSF 描述仪器成像模糊，不是某一个星系的形状。WCS 相当于照片附带的坐标换算说明。

程序也能读取主图层中的普通二维 FITS。没有提供 RMS 时会从图像估计噪声；估计值不等于测得的完整误差模型。缺少有效 PSF 时，当前 PSF 比较前景模型不能正常建立，这会限制后面的稳健性判断。

### 3.2 输入一个文件夹时

程序优先找“文件夹名.fits”；没有这个文件时，要求文件夹里恰好有一个 .fits。多个文件无法确定目标时会报错，不会随便挑一个。

这意味着 analyze 命令输入的是一个对象文件夹，不是让它自动扫描整个 A 文件夹。批量分析需要外层脚本逐对象调用。

### 3.3 PNG 为什么不是等价替代品

PNG 是为了显示而生成的图，亮度可能经过拉伸或裁切。本项目将 PNG 转灰度，并使用简化检测网格。它没有原 FITS 的标定通量、RMS、PSF 和天空坐标信息。

因此，PNG 可以辅助了解形状，但程序从 PNG 算出的数值不能冒充原始科学光度或可靠显著性。本版对 PNG 的科学分级还没有完成专门验证；正式工作优先用原始 FITS。

## 4. 总流程：从一张 FITS 到一个可阅读报告

1. 读取数据，检查尺寸和异常数值。
2. 估计天空背景、检测亮源，确定要围绕哪个前景中心分析。
3. 建立前景光模型，得到主要残差图。
4. 用不同阈值和分割参数寻找残差亮块。
5. 在可能的圆/椭圆路线附近继续搜索漏掉的真实像素。
6. 建立另一种前景模型，供比较，不把它当独立观测。
7. 保存所有候选的像素掩膜，统一重新测量。
8. 在评级前合并、去重证据；记录没有纳入的原因。
9. 用一套固定规则判断构型、疑点和等级。
10. 从源测量重放检查；生成对外等级、报告和可追溯记录。

前 1—7 步主要是“测量”，第 8—9 步是“解释”，第 10 步是“一致性检查与输出”。这三种工作不能混为一谈。

## 5. 前半段如何从像素找出结构

### 5.1 数据清理不是美化

程序先检查图像是否为二维、噪声图是否同样大小。NaN 等无效数值会被替换成可计算的估计值，同时保存整体有效比例。

这种替换是让算法能够继续运行，不意味着修复了真实观测。当前对坏像素和局部缺测的处理还不够完整，所以不能因程序没有报错就默认所有位置的数据都可靠。

### 5.2 找到前景中心

默认以小图中心作为目标位置的先验，也就是“我们预期要看的对象大致在这里”。

程序先检测亮源，选择靠近目标位置的源，再在限制范围内找它的亮峰作为分析中心。如果两个候选同样接近，或者对象偏离太远，会记录中心不明确。

当前典型限制是离参考位置不超过 10 像素；最近两个源的距离差小于 2 像素时可触发歧义。用户可以明确提供 x、y 来指定偏心目标。

中心选错，半径、切向方向和环形搜索都可能跟着错。没有中心不确定性，不代表中心就绝对正确。

### 5.3 为什么减掉前景亮光

想象明亮路灯旁有一条暗线：暗线可能确实存在，但被路灯的亮光淹没。我们可以估计“如果只有路灯，照片应该是什么样”，再把这部分亮度减掉。

本项目类似地估计前景星系光，然后计算：

    残差 = 原始图像 - 前景光模型

- 正残差：比模型预计的更亮。
- 负残差：模型预计得过亮，减完出现负值。
- 零附近：数据和模型接近。

负值不代表天空真的有“负光”，而是数据与模型的差。

### 5.4 第一种前景模型：一圈圈拟合亮度

首先用 Photutils 拟合等光度线，也就是亮度差不多的一圈位置，近似为椭圆。将各圈的亮度、扁率和方向平滑后，构造完整前景光图。

如果这一步失败，程序回退为更简单的径向模型：按到中心的距离分圈，取每圈亮度的中位数，再插值填成一张图。

回退后仍能得到残差，但会明确记录主拟合失败。圆对称近似可能留下假结构，也可能把真实弧吸收进前景；这些风险本版尚未完全校准。

### 5.5 SEP：先圈出亮块

SEP 是一个现成的天文源检测库，能估计背景、识别高于噪声的亮区，以及把粘在一起的亮区拆开。[SEP 文档](https://sep.readthedocs.io/en/stable/)

“拆开粘连亮块”叫去混合或 deblending。拆得过少，星系和弧可能粘成一团；拆得过多，一条弧可能碎成许多块。

所以程序不是只用一组拆分设置：默认尝试 3 种分层数量与 4 种拆分强度，即 12 组组合，观察哪些检测较稳定。

不同设置反复找到同一块，只说明算法对这些设置不太敏感；因为使用同一张图，不能当成十二次独立观测。

### 5.6 多阈值检测：从暗到亮检查

另一条检测线在残差信噪比图上逐层设置门槛。默认约为 2、2.58、3.34、4.31、5.57、7.19、9.29、12。

较低门槛能找较暗结构，也更容易带入噪声；较高门槛通常只剩亮的部分。同一候选能在多少层保留一定连通面积，会被记录为“阈值稳定性”。

它不是“透镜置信度”：真实的暗弧也可能只出现在低门槛层。

### 5.7 几何路线搜索：沿着可能的弧再找一遍

全图分割可能漏掉暗弧或将弧粘在前景上。程序根据已有结构或前景中心提出圆/椭圆搜索带，沿带再次检查原来的残差像素。

默认搜索范围约为中心外 4—25 像素；尝试的短轴/长轴比为 1.0、0.9、0.8、0.7，方向按 30 度间隔尝试，中心可以在小范围内移动。最终保留有限数量的路线。

重要区别：

- 路线是“往哪里找”的建议。
- 恢复结构是沿路线找出的实际信号像素。
- 画出一条完整椭圆，不代表整条椭圆都被观测到了。
- 这里的恢复不是 AI 补图，不会把缺失段凭空画成观测证据。
- 能沿某条路线找到信号，也不自动证明其为透镜；搜索过很多路线会增加碰巧找到像弧噪声的机会。

### 5.8 model chain 图的颜色

在当前候选对照图中：

| 颜色 | 含义 |
|---|---|
| 橙色 | SEP 找到，但未被当前几何路线支持的部分 |
| 绿色 | SEP 检测与几何路线相符的部分 |
| 紫色 | 几何路线搜索补充找到的部分 |

这是来源颜色，不是 A/B/C 颜色，也不是“绿色一定真实、橙色一定污染”。不同诊断图可能使用不同图例，始终先看该图自己的说明。

### 5.9 第二种前景模型：多团平滑光叠加

比较模型使用 MGE，可直观理解为把十团大小不同的平滑椭圆光斑叠加，拟合星系从中心到外围的亮度，再模拟 PSF 带来的模糊。

当前光斑共用固定几何方向和扁率；优化器求各团光有多亮，并剔除明显偏离拟合的点。它不是完整的可任意变化星系模型；当前拟合也没有完整纳入每像素 RMS 权重与前景误差传播。

主模型与比较模型用的是同一张观测图。比较的作用是发现“这个结构是否过分依赖某种前景扣除方法”，不是再得到一份独立天文证据。

## 6. 后续到底测哪些数值

### 6.1 名义孔径信噪比

“孔径”在这里就是选定的一片像素，不一定是圆。

计算大意是：把这片像素的残差信号加起来，再除以这片区域的噪声估计。

    总信号 F = 区域内残差值之和
    噪声估计 σ = 各像素 RMS 的平方相加后开平方
    名义 SNR = F / σ

例如 25 个像素每个多出 1 单位信号、各自 RMS=1，得到 F=25、σ=5、SNR=5。每个像素都不到 2 倍噪声，但合起来仍可能有可测信号。

它叫“名义”SNR，是因为忽略了像素之间的噪声关联、前景拟合误差和大量搜索带来的选择效应。不能把 SNR=5 直接翻译成“这就是可靠的五西格玛发现”。

### 6.2 位置与形状

| 测量 | 通俗解释 | 注意事项 |
|---|---|---|
| 像素数 | 这块区域有多少格被选中 | 不等于独立测量次数 |
| 质心 | 所有选中像素位置的平均点 | 当前重测是像素位置平均，不是通量加权重心 |
| 质心半径 | 平均点到前景中心的距离 | 半环/整环的平均点会向中心靠近 |
| 像素中位半径 | 每个像素先量距中心的距离，再取中间值 | 更适合描述环光实际分布在哪里 |
| 方位角 | 结构在中心的哪个方向 | 0°方向约定要按字段/图例读取 |
| 总角跨度 | 从中心看，覆盖的最小连续扇形有多大 | 中间可能有空隙 |
| 角度占有 | 把一圈分成 72 个 5°小格，实际有像素的格子有多少 | 比单看端点跨度更能识别稀疏分布 |
| 整体轴比 | 整体长方向相对短方向有多长 | 此字段长/短≥1；搜索椭圆的 q 是短/长≤1，不能混用 |
| 切向偏角 | 延伸方向与“绕中心方向”偏离多少 | 0°近似沿圆周，90°近似指向中心 |
| 核区像素重叠 | 有多少选中像素真正落进核区 | 不再由质心位置代替 |

### 6.3 为什么环要看局部方向

直线可以用一根长轴描述，整圈的圆却没有明显长轴。

当前算法把周围分成 12 个 30°扇区：某段至少有 5 个像素，并且足够拉长，才测该段方向；再统计这些可测段中，有多少接近切向。

“局部切向比例 0.67”表示参与测量的局部段中约三分之二满足方向条件，不表示透镜概率 67%。无法测方向是未知，不是测得方向错误。

环带宽度目前用像素半径的第 90 百分位减第 10 百分位，再除以中位半径。百分位可以理解为把数值从小到大排队后相应位置的值。这个量依然可能受真实椭圆形状影响，不是普遍的环判据。

### 6.4 两个前景模型的比较量

旧字段名 survival_fraction 容易误导。其真正含义是：第一张残差选出的区域中，有多大比例在第二张残差里超过逐像素检测门槛。

它既不是剩余通量比例，也不是真实概率。

本版额外读取第二张残差里同一整片区域的有符号总通量和名义 SNR。这样能区分：

- 单像素都较暗，但整段仍有正信号；
- 整段接近零；
- 整段明显变为负残差；
- 根本没有可用比较模型。

前两种不能混为“完全抹掉”，最后一种不能混为“没有信号”。

## 7. 测到的结构如何进入评级

### 7.1 测量记录与最终证据集不是同一份表

源 Observation 是最初保存的测量记录。它还可能保留早期阶段的“通过、待看、污染风险”等标签。

本版在评级前，用完整候选像素重测结果构造一份新的规范化证据集。原记录不改，新的记录单独保存为 reasoning_observation.json。

这解释了为什么旧 signal-audit 图的标签与最终纳入状态不一定一模一样：前者是中间处理标签，后者由完整测量统一决定。判断最后用了谁，应查 evidence_preparation，而不是只看旧标签。

### 7.2 统一纳入条件

对完整交接的候选，当前统一检查：

1. 有可用的像素测量。
2. 通量和 SNR 不是无效数值。
3. 至少 5 个像素。
4. 总残差通量为正，名义 SNR 至少 4。
5. 不是前面已经纳入的完全相同像素掩膜。

不满足的候选仍然留档，并注明具体原因。被纳入只是“这块信号值得解释”，不是“它已被证实为透镜”。

路线来源、旧隔离标签、质心近核、比较图超阈比例为零，不直接挡住此处的纳入。

一个旧正式结构若对应同一个候选，会被新测量替换一次，避免一块信号算两次。没有被完整交接覆盖的旧结构仍保留。完全重复掩膜能去重，但部分重叠掩膜尚未全面处理。

### 7.3 场景统计重新计算

新增或移除结构后，半径分散程度、角度占有和方向统计也必须更新。新版从新集合重算。

如果缺少计算所必需的像素角度数据，就记录不可用，不用旧数字假装代表新集合。原文件夹中的 A/B 字样只供外部对照，不进入评级规则。

## 8. 评级规则：实际代码如何分支

先记住：以下是 v0.21 的计算规则，不是 Euclid 规定的像素阈值，也不是已通过独立验证的物理定律。

### 8.1 先检查可用性

源记录必须标记可用，中心不能标记为有歧义；有效数值比例至少 0.99，背景噪声与残差噪声必须为正。

这类检查失败时，内部选择 insufficient_for_grading，意思是暂不评级，对外显示 unknown。

### 8.2 再寻找不同形态组合

下表概括当前主要条件，不把源码中的 supported 翻译成“物理上已证实”。

| 程序中的形态分支 | 大白话 | 当前主要条件 |
|---|---|---|
| 切向弧 | 大致绕前景中心弯着走的长条 | 整体轴比≥1.5、偏离切向≤35°、跨度≥20°；或通过局部弯曲判据 |
| 较稳健的单弧 | 较长、不是全部落在核区的切向弧 | 跨度≥30°，至少在部分阈值检查中保留，并检查比较孔径正信号 |
| 局部环/弯曲长结构 | 一段围着中心延伸的环带 | 占有角≥90°，相对径向宽度≤0.5，至少3段局部方向可测，切向比例≥0.67，不全部位于核区 |
| fold 候选 | 两段靠近、可能对应一对靠近的透镜像 | 两个切向结构方位差≤60°，像素中位半径满足相对差限制 |
| cusp 候选 | 同一侧三段靠近的候选像 | 三个切向结构所在扇形≤100°，逐对满足半径兼容条件 |
| 径向弧候选 | 延伸方向较接近指向中心 | 与切向偏离≥65°、整体轴比≥1.5；有切向伴随结构时可进入更强分支 |
| 紧致多像候选 | 几个不呈长弧的小像 | 至少4个紧致结构，共同半径代理及方位跨度≥180°等条件 |
| 场景整体协调 | 多块结构大致围绕同一中心 | 至少2块、半径变异系数≤0.30，方向协调且角度覆盖满足60°/90°等分支要求 |

“变异系数”就是半径的分散程度除以平均半径。fold/cusp 使用的相对半径差是“两个半径的差÷两者平均值≤0.30”。本版没有把半径要求全部删除，只把这些比较中的半径改成更合适的像素中位半径。

fold/cusp 是物理构型名称，但当前只计算了简化的形态代理，没有检验完整的透镜映射。名称不能当成完整物理诊断。

旧 ring_candidates 字段也仍有兼容解释分支，但当前新图像流程不再输出这个旧环候选列表；新环形判断主要依靠结构的局部形态测量。

### 8.3 比较模型现在怎样影响等级

当前更强的构型分支检查：比较模型成功，并且相关结构在同一孔径中的名义 SNR≥4。不同构型需要检查一个结构或一组结构；最后还会要求至少一个相关结构得到这种比较支持。

这替代了此前将超阈像素比例≥0.75当成稳健性条件的用法。没有比较孔径测量，不会凭空补一个正值；因此只读取缺少新测量的旧 JSON，可能比重测原像素更保守。

若当前优先关注的一组结构在比较残差中全都出现名义 SNR≤−4，则记为尚未解决的前景模型冲突，输出 unknown。不是“任何一个像素为负就 unknown”，也不是“证明它是伪影”。

注意：4 仍是沿用的工程门槛，尚未完成搜索显著性标定。不能把这次更名和公式修正夸大成解决了所有低信噪比问题。

### 8.4 非透镜解释实际检查到了什么

程序列出五类解释：透镜、本征星系形态、并合/相互作用、前景减除/PSF伪影、噪声/坏像素/投影源。

但列出名称不等于完成了五种物理模型比较。

- 附近额外亮峰：本版只记问题，不直接认定多核或并合，不直接压低等级。
- 前景/PSF伪影：还没有专门的完整来源诊断，通常记录 unknown。
- 本征形态：仍保留旧的组合代理。当向内连接结构数≥2、不对称代理≥0.65、核区绝对残差占比≥0.5同时成立时，可构成竞争解释。这仍是有待检验的薄弱环节。
- 不对称代理：将残差旋转180°后比较差异；它不等于测得真实潮汐尾。
- 坏像素、光谱、颜色一致性等信息可能缺失或只进行了很粗的检查，报告不能当作这些检查全部做完。

### 8.5 最终按顺序判断，不是给各指标加分

| 顺序 | 条件概括 | 内部结果 |
|---|---|---|
| 1 | 数据/中心不可用，或相关结构存在上述有符号模型冲突 | insufficient_for_grading |
| 2 | 通过当前清晰构型规则，且没有当前规则认定的同样强的替代解释 | A |
| 3 | 清晰构型成立，但存在这种竞争解释 | B |
| 4 | 有可测信号及方向/关系支持，但未达到清晰构型条件，且没有同样强的替代解释 | B |
| 5 | 只保留较弱的形态或候选支持 | C |
| 6 | 没有足够支持上述类别的结构 | X |

代码也存在“有可信残差信号、没有明确透镜关系时给 C”的分支。这比严格的视觉透镜特征定义更宽，是当前限制，不应包装成已经完善的 C 级判断。

一旦前面的分支命中，就不继续随意改判。所有决定来自同一个最终证据集，不再做第二个候选评分然后取较高者。

## 9. ABC、unknown 和官方分数怎么理解

Q1 风格的直观含义：A 有充分视觉把握，B 很可能但仍需补充确认，C 可能但也能作非透镜解释；X 为非透镜。Q1 目录由十位专家判断汇总并校正个人倾向，A>2、B为1.5—2、C为>1—1.5，不能用单个 agent 的类别冒充汇总分。[Euclid Q1 §6、§8.3](https://arxiv.org/html/2503.15324v1)

本软件当前输出的是未校准的规则判断，不是自动取到了官方目录标签，也不是概率。

必须看 summary.json 中的 published_grade：

| 对外结果 | publication_reason 示例 | 实际含义 |
|---|---|---|
| A/B/C | provisional_q1_style_category_not_catalog_calibrated | 审计通过的暂定规则类别，尚未完成目录校准 |
| unknown | insufficient_evidence_or_unresolved_processing | 证据不足或处理冲突，无法可靠评级 |
| unknown | audit_failed | 本次推导/引用/重放检查失败 |
| unknown | non_lens_vote_X | 内部实际上判断为 X，不是“没看清” |

所以 unknown 当前是对外兜底结果；必须连原因一起读，不能把所有 unknown 当成同一种天文学结论。它不是 Q1 官方新增的一档。

official_expert_score、provisional_expert_score 等数字字段保持空。空不是0分，而是“没有提供这个量”。A+所涉及的独立科学价值信息也不应该被理解成比A更高的透镜概率。

## 10. 审计、可复现和可追溯分别保证什么

### 10.1 审计

检查引用的事实是否存在、候选记录是否完整、是否重复使用相关证据、有没有混入外部答案，以及等级与解释是否对应。

本版还从源 Observation 重新执行同一确定性决策，比较新的证据集、证据档案和判断是否一致。原判断被改动时，重放可以揭示不一致。

这是“同一道计算重复算，结果是否一致”，不是“另外一位天文学家独立认可”。所有规则存在的共同错误，重放本身抓不出来。

### 10.2 可复现

同一输入、同一代码、同一参数和计算环境，再跑应得到相同结果。依赖库是程序使用的现成工具；版本变了，数值计算可能变化，所以必须记录版本。

不承诺不同机器、不同数学库一定逐位一致；需要明确比较哪部分：像素数组、测量值、候选集合，还是最终类别。

### 10.3 可追溯

遇到“C1为什么没纳入”时，能够从报告找到候选记录、测量值、规则参数和像素掩膜，而不是只能听到一句笼统解释。

SHA256 是文件/数组内容指纹：用来发现内容是否变化。指纹不验证天文结论，也不是凭它就能恢复文件，因此还保留源码副本。

当前明确留档：输入与数组指纹、Python及主要依赖版本、平台、数值线程环境、运行参数、源码副本、合并前后测量和决策条件。没有执行的“删除关键证据再测”检查，写 not_tested，不写成已经通过。

## 11. 输出目录里每个文件该怎样看

| 文件 | 新人用法 |
|---|---|
| report.md | 先读这个：等级、疑点、结构纳入表和条件说明 |
| summary.json | 机器可读的完整判断；正式消费 published_grade 和 publication_reason |
| observation.json | 图像流程最初输出的结构化测量 |
| source_observation.json | 本次推理读取的源测量副本 |
| reasoning_observation.json | 真正进入本次评级的合并后测量 |
| reasoning.json | 证据档案、解释及推理轨迹；与 summary 的展示用途不同 |
| observation_summary_cn.md | 图像测量的中文摘要，不代替最终报告 |
| vision_artifacts.npz | 压缩保存的原图、残差、模型、各候选掩膜等数字数组 |
| vision_segmentation.fits | 用编号图层表示不同分割和候选区域 |
| vision_manifest.json | 图像处理阶段的参数、来源和产物记录 |
| run_manifest.json | 本次运行的代码/输入指纹、环境与参数 |
| code_snapshot/ | 当次运行的源码副本 |
| 各种 .png | 供人查看的过程图，不是新的观测数据 |

JSON 是“字段名：数值”的文本记录；NPZ 是多张数字表的压缩包；Markdown（.md）是适合阅读和排版的文本。

常用图：

- vision_model_chain.png：模型链处理和候选来源。
- candidate_handoff_review.png：同一候选在原图、主残差、比较残差上的位置。
- vision_snr_threshold_process.png：不同信噪比门槛下出现哪些区域。
- vision_sep_consensus.png：分割参数变化和检测稳定性。
- vision_geometric_path_search.png：搜索了哪些几何路线。
- vision_foreground_model_comparison.png：两种前景处理如何不同。
- vision_field_context.png：原生 FITS 全场、裁剪框、搜索环带与候选位置。
- vision_target_selection.png：仅在目标竞争、中心先验冲突或人工覆盖时输出的路由审计图。

RGB 预览不再作为独立上下文图输出。当前评级没有完成标定颜色的一致性检验；不同图的明暗拉伸也可能不同，不能只凭显示亮度比较通量。

建议阅读顺序：published_grade/原因 → 无标注原图 → 候选对照图 → 纳入表 → 命中规则 → 原像素和运行记录。不要把过程图里的“promoted”读成“升为 A”；它首先是阶段性结构交接标签。

## 12. 新人怎样运行

### 12.1 准备软件环境

需要 Python 3.11 或更高版本；项目当前验证使用的具体环境以 run_manifest 为准。在 PowerShell 中进入项目目录后，可以安装项目及测试依赖：

```powershell
Set-Location 'G:\Astronomy\LensAgent - 副本'
python -m pip install -e ".[dev]"
```

这只是使用说明，不代表本次介绍又执行了一次安装。`-e` 表示本地源码的修改会直接被使用；因此实验前应保留源码和参数快照。

### 12.2 完整处理一个对象

下面使用已经存在的 5591 样本作例子；输出目录请换成尚未使用的新名字：

```powershell
python -m expert_agent.cli analyze 'G:\Astronomy\New data\A\102021493_NEG586398445479765591' --output 'outputs_newcomer_demo'
```

这会从 FITS 开始经过图像处理、测量和评级。也可以使用安装后提供的 lens-agent 命令，含义相同。

常见参数：

| 参数 | 含义 |
|---|---|
| --output | 输出目录 |
| --band | 指定波段，默认 VIS |
| --center-x、--center-y | 成对提供目标参考中心；只提供一个会报错 |
| --ring-inner、--ring-outer | 主要环状分析范围的内外半径，单位像素，默认4和25 |
| --flat-output | 直接写入给定输出目录，不再按对象加一层目录 |

改变中心、范围或波段会改变测量，不是单纯换一种显示方式。不要为得到想要的等级随意调参数。

### 12.3 只重新解释已有测量

```powershell
python -m expert_agent.cli reason 'G:\Astronomy\LensAgent - 副本\outputs_deterministic_review_20260907\full_fits\102021493_NEG586398445479765591\source_observation.json' --output 'outputs_newcomer_reason_demo'
```

reason 不重新执行 FITS 图像处理，也不会自动补测旧 JSON 中缺失的像素指标。它的运行清单可能记录现有输入文件指纹，但科学判断仍消费 JSON 测量；两件事要区分。

“保存像素重测”则是另一种验证操作：从 NPZ 重新提取候选指标后再评级。它比纯 JSON 重放多了一步，但依旧不是完整重跑前景拟合。

### 12.4 成功和失败

- 退出码0：程序正常完成且决策审计通过，不保证一定为 A/B/C，也不保证科学结论正确。
- 退出码1：文件、依赖、数据或其他执行错误。
- 退出码2：决策审计失败，不能把内部建议类别当有效 ABC。

若提示前景拟合失败，先看是否已使用回退模型，以及最终是否有比较测量；不要只凭一条警告认定整个程序崩溃。

当前命令会向指定目录写文件，不具备“无论怎样都不会覆盖旧结果”的保证。每次使用新的输出目录最稳妥。原始输入读取与输出目录也应分开。

### 12.5 跑测试

```powershell
python -m pytest -q
```

这是检查程序行为的测试，不是拿所有天体重新做专家盲评。

当前专家工作流的实际执行顺序是 ExpertAssessmentAgent → DecisionAudit → ReportWriter。证据合并函数由 ExpertAssessmentAgent 在裁决前调用，不是第二位评分专家。

关键文件：preprocess.py 负责读图和前处理；detectors.py 负责检测与路线；foreground_models.py 负责比较光模型；candidate_handoff.py 负责候选重测；evidence_preparation.py 负责统一证据；expert_assessment_agent.py 负责判断；decision_audit.py 负责检查；report_writer.py 负责报告。

### 13.3 配置文件里有数值，不等于仍在使用

core/config.py 同时保留当前参数和历史兼容参数。例如旧候选二次评分的“clear SNR=7”“伴随结构半径比≤3”等字段还在配置中，但相应独立评分实现已移除，不能当成本版生效的 A/B 规则。

0.75 也仍可见：它还用于旧字段解释或风险提示，不再是本版比较孔径稳健性的主门槛。准确理解一个参数，要看执行链中哪一行代码读取它，而不只搜索到它的定义。

### 13.4 维护项目的原则

修改前保留当前源码和对照结果；一次明确说明改什么；先测最小合成例子，再跑固定开发回归集；最后用没有参与调参的独立样本验证。

不要只盯“A样本有没有更多升A”，也要看B被错升A、C/非透镜误报，以及unknown是否异常增加。正式评估不应该让输入文件夹名、已知标签或旧报告答案影响评级。

## 14. 本版与“上一版”的逐项对比

本节的上一版特指本轮修改前保存的工作目录快照：outputs_deterministic_review_20260907/before/source_snapshot。它的包版本号仍写0.19.0，但已包含此前候选补充评级修改。因此不把它简单当作最早原始v0.19，也不虚构一个独立发布的v0.20。

| 项目 | 修改前快照 | v0.21实验版 | 新人应怎样理解 |
|---|---|---|---|
| 输入 | FITS/PNG | 保留 | 没换成截图喂聊天AI |
| AI方式 | 固定算法和规则 | 保留；未接多模态 | 不是换了一个更大的模型 |
| 前景与路线核心算法 | 等光度线/径向回退、SEP、几何搜索、MGE比较 | 主体保留 | 本次不是全面重写图像算法 |
| 候选证据进入时机 | 主解释器判断后，再作候选补充判断 | 所有完整候选在一次判断前合并 | 先把材料摆齐，再判断 |
| 最终合并 | 两套内部判断取较高等级 | 取消取高，只保留一次裁决 | 不再天生只能升级 |
| 多亮块 | 可以直接作为并合竞争解释压低等级 | 只记额外亮峰待核查 | 亮块不是已证实的星系核 |
| 近核判断 | 候选质心到中心距离 | 实际像素与核区重叠 | 环的质心在中心，不等于环光在核里 |
| 环结构数量 | 部分旧环分支要求至少两个结构 | 允许一个结构；加入局部弯曲支持 | 不因一条弧没有被切成两块而受罚 |
| 构型半径 | 部分比较使用质心半径 | 改用像素中位半径 | 测环光在哪里，而不是测平均点在哪里 |
| 比较稳健性 | 主要依赖超阈像素比例，如0.75 | 检查有符号同孔径名义SNR | 整段较暗但有信号，与真无信号分开 |
| 零比较占有率 | 可被解释为污染并隔离 | 不再直接判污染或禁止纳入 | 全部略低于像素门槛也可能有总信号 |
| 显著负比较残差 | 没有这版统一冲突处理 | 相关结构整组冲突时unknown | 承认模型处理不确定，不假装识别物理来源 |
| 原/新场景统计 | 可能使用旧结构集合的统计 | 随合并后集合重算；缺数据则不可用 | 换了名单，统计表也重做 |
| 重复候选 | 没有本版基于指纹的完整掩膜去重 | 相同掩膜不重复纳入 | 同一块光不能冒充两幅像 |
| 数字专家分 | 某些升级路径写入2/3分 | 所有单agent数字分保持空 | 类别不是十位专家汇总分 |
| 目录C界限 | 只映射A/B | 加入官方文中C区间 | 修正映射语义，不制造概率 |
| 审计 | 主要是字段检查及基于最终类别的再次计算 | 从源测量重放完整判断和证据 | 检查结果能否从材料重新得到 |
| 审计失败 | 仍可输出内部等级、正常退出 | 对外unknown，命令返回2 | 没通过检查的结果不得冒充有效ABC |
| 对外主字段 | 主要读取内部vote | published_grade加原因 | 内部建议与正式发布分开 |
| 删除证据检验 | 未执行时可能用启发式写结果 | 明确not_tested | 没做过就不写成做过 |
| 复现记录 | 有图像过程记录，但不足以覆盖新判断 | 增加源/规范化测量、代码指纹/副本、依赖和决策条件 | 更容易查清哪次改动影响了什么 |
| 历史结果 | 多批输出 | 原文件保留，本轮单独目录 | 留档不是维持两套当前评分模式 |

## 16. 当前能力边界与新人必须记住的误区

1. 看见弧状信号，不等于确认透镜；残差里有弧，更不能自动确认。
2. 前景模型成功，是数值拟合完成；不等于星系结构已被正确分离。
3. 多模型一致，是同数据的稳定性线索；不是多次独立观测。
4. 掩膜表示真实选中的像素，不代表这些像素物理来源已经确定。
5. 比较超阈比例为0，不等于总通量为0。
6. 质心位于核区，不等于环光位于核区。
7. 代码仍保留近似形态门槛，不是已经摆脱规则依赖。
8. 彩色诊断图存在，不等于已完成颜色物理检验。
9. `supported` 是通过当前条件，`unknown` 是未知或未完成，`future` 是未来计划，`not_tested` 是没测；它们不能互相替代。
10. 清晰构型分支尚不能彻底排除旋臂、本征环、PSF或减除伪影；B高估就是当前证据之一。
11. 新增4的比较SNR条件仍是未校准的工程阈值，不是更换公式后就自动获得物理可靠性。
12. 测量可复现、解释可追溯、类别符合专家，分别是三项要求；前两项进步不自动保证第三项。

## 17. 用一个虚构例子把整条链串起来

以下只演示思路，不是额外真实样本结论。

假设图中央有一个亮星系，旁边露出弯曲暗线。程序先确定中心、估计并减去星系光。SEP圈出弯线较亮部分，几何路线在原残差里找到另外一些像素，分别贴C1、C2等标签。

C1有30个像素、正通量、名义SNR=8；C2只有3个像素。完整测量阶段保留二者记录。证据合并将C1纳入，把C2记为低于当前最小面积，不会删除C2的历史掩膜。

C1虽呈半环，质心靠近中心，但实际像素都在核区外。程序不会因为平均点靠里而直接隔离它。它在比较残差里每个像素都没超过2倍噪声，可整个孔径名义SNR=5，因此不是“被完全抹掉”。

接着程序检查局部切向、角度占有、宽度与替代解释。若通过当前清晰构型规则，可给暂定A；若只满足部分条件则可能B/C；若模型间相关结构明显符号冲突，则unknown。不是仅凭上面两个SNR数值就能确定等级。

最后，程序从源测量再算一次；若出现不一致，不发布ABC。你可以从报告沿着C1的引用找到原来的像素掩膜和参数。
